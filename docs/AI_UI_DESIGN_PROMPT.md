# AI Gist UI Design Prompt (3.0)

Use this document as a mandatory system prompt whenever creating or modifying AI Gist UI under `src/renderer`, on desktop, desktop-Web and the Ionic mobile app.

The visual reference is the "AI Gist 界面重设计" Claude Design canvas: page `V5（完整）` for screens and page `组件库` for foundations, controls, overlays, data display and business components. When this document and a board disagree, follow this document and raise the difference.

## Product intent

AI Gist is a local-first productivity tool. Its interface should feel calm, precise, durable, and easy to scan. Daily prompt use (fill variables, copy) is more important than editing or debugging. Keep complexity inside the implementation, not in the visible interface.

The desktop design language is **bordered panels on tinted surfaces, with shadows reserved for overlays**. Bright azure blue carries brand, actions and selection; amber is only an accent for the favorite star. Do not introduce a second visual language.

## Tokens

- All values come from `src/renderer/design-tokens.json` through the CSS variables generated by `theme/index.ts`. Never introduce page-local palettes, hard-coded light/dark colors, arbitrary radii or arbitrary shadows.
- Every color token has a light and a dark value. Verify both themes; never add a page-specific `prefers-color-scheme` query.

## Typography

- Desktop uses five sizes only: 22/600 page titles, 16/600 section, panel and modal titles, 14/400–500 body, controls, menus and table cells, 13/400–500 form labels, secondary copy and table headers, 12/400–500 time, counts, shortcuts and badges. Never go below 12px.
- Weights are 400, 500 and 600 only.
- Body line height is 1.5; prompt body text uses 1.8.
- The monospace family is only for variable names, shortcut keys, code, paths and model IDs.

## Spacing, radius, icons

- Spacing steps: 4 (icon to text), 8 (between buttons), 12 (compact groups), 16 (panel padding, section gaps), 24 (page padding), 32 (large separations).
- Radius: 6 controls, 8 panels, cards and images, 10 modals and drawers. Pills (capsule chips, mobile tab bar) are fully rounded.
- Desktop icons are `@vicons/tabler`: 14px inside inputs, 16px in buttons and menus, 18px in the navigation rail. Wrap them in a sized `NIcon`. Icon-only buttons always carry `aria-label` and a tooltip.
- The logo is the app icon image (`assets/images/logo.png`) used as-is, with no extra background or border.

## Desktop layout

- Shell: navigation rail (`--rail-width`, surface secondary, right border) + content + status bar (`--statusbar-height`, top border).
- Secondary lists (prompt library, model list) are `--list-width`; navigation sidebars (settings, folders) are `--nav-width`; the right-hand panel (variables, AI, version history) is `--side-panel-width`. All three use `--surface-secondary` and a single border toward the content.
- Page padding: prompt document 40, settings and detail pages 32, lists and tables 24. Prompt bodies and settings content are capped at `--reading-width`.
- Overlay sizes: confirmation dialogs (unsaved changes, delete, shortcut binding) 460; form dialogs (category management) 560; multi-step dialogs (add model configuration, sync conflict) 880; workspace dialogs with a list and an editor (quick optimization) 960; drawers (usage history) 420; launcher 800.
- Below 1200px the right-hand panel collapses into a toggle and drawer; below 960px the secondary list moves into a drawer. Tables keep their row actions at every width.

## Components

### Surfaces

- Panels: `--surface-primary`, `1px solid var(--border-default)`, radius 8. Panel headers and footers use `--surface-secondary` with a separator. Muted inner groups use `--surface-secondary` without another border.
- Cards, panels, tables, toolbars and navigation never carry shadows. Hover changes the surface to `--surface-secondary` and the border to `--border-strong`.
- Prefer bordered Naive UI `NCard` or the shared `components/ui` primitives. Structural `NCard` components are never `bordered="false"`.

### Buttons

- Heights: 22 for actions inside panel headers, 28 for setting rows, toolbars and forms (the default), 34 for page-level primary actions (copy, adopt, save as new version), 40 only for large standalone calls to action.
- One primary button per local context. Other actions are outline (default), secondary (tinted, no border), ghost (text) or danger. Destructive confirmations use a solid red button and require confirmation for irreversible changes.
- Table row actions are icon-only buttons with tooltips.
- A dropdown with only one action becomes a direct icon button with a tooltip.

### Inputs and choices

- Inputs and selects match button heights; focus shows `--accent-primary`-tinted border plus `--focus-ring`; errors use `--accent-error` border and a 12px message.
- Segmented controls choose between a few exclusive options; tabs switch content in the same region (bottom indicator in `--accent-primary`).
- Variable option fields with three or fewer options are laid out as buttons; more than three use a select.

### Navigation and selection

- Navigation items (rail, settings navigation, folder tree, menus) when selected: `--accent-soft` background, `--accent-soft-text` text, icon in `--accent-primary`.
- Content items (prompt list rows, table rows, cards) when selected: `--accent-soft` background, text unchanged; batch-selected cards add an `--accent-soft-border` border.
- List rows that drive a detail pane (prompt library list, model list, version history, quick optimization list) follow the navigation rule: `--accent-soft` background and the row title in `--accent-soft-text`, so the current row stays distinct from the hover background.
- Never mark selection or emphasis with a coloured bar or coloured border on the leading edge (no `inset 2px 0 0 var(--accent-primary)`, no accent `border-left`). The tinted background is the whole selected state.
- Hover on rows and menu items uses `--surface-tertiary`.
- Unsaved work shows a `--accent-warning` dot in lists and a warning bar at the top of the page.
- Naive UI Menu paints hover and selection through `.n-menu-item-content::before`; configure these states through Menu theme overrides and never add a second background to `.n-menu-item-content`. Do not add color or background transitions to menu items: a fading previous item reads as a second selection.
- Do not use large blue blocks, gradients, glowing borders, scale animations or "AI-style" effects.

### Tags, counts and status

- Tags are neutral: `--surface-tertiary` background, `--content-secondary` text, 22px high, radius 5. Outline tags use `--surface-primary` with an inset `--border-default` ring. Status tags use the status `-bg` and text colors.
- Category color appears only as an 8px square dot (radius 2) or a mobile icon tile, never as a large fill.
- Status dots are 6px. Counts are 18px pills on `--surface-tertiary`.
- Shortcut keys use the `kbd` style: mono 12px, `--border-default` with a 2px bottom border.

### Prompt content

- Filled variables in prompt bodies: `--variable-bg` background, inset `--variable-border` ring, `--variable-text` value preceded by a 12px `--variable-label` name.
- Missing required variables: `--surface-primary` background, dashed `--variable-missing` outline, warning-colored name.
- The variable being edited adds `--focus-ring`.
- Variable-name mode shows the name in the monospace family.
- AI insertions use `--diff-insert-*`; deletions use `--diff-delete-*` with a strike-through.
- While an AI suggestion or a version comparison is shown, the body is read-only and the copy bar is replaced by the suggestion or restore bar.

### Overlays and feedback

- Only overlays have shadows: dropdowns, tooltips and popconfirms use `--shadow-popover`; modals and drawers use `--shadow-overlay` over `--overlay-backdrop`.
- Modals: radius 10, 52px header and footer on `--surface-secondary` with separators, 20px body padding, 16px titles. Footer buttons go from secondary to primary, left to right.
- When using a raw `NModal` without a preset, its first rendered child must be a `div` or Naive UI `NCard`. Do not use semantic elements such as `section`, `main`, `article`, or `aside` as the modal content root: Naive UI 2.41's focus trap locates custom modal content by its rendered `DIV` root.
- Messages appear top-center and disappear after three seconds. Inline alerts use the status `-bg` and `-border` colors.
- Empty states: a 56px bordered icon box on `--surface-secondary`, a 16px title, a 13px description and at most one primary action.
- Opening a prompt from the card, table or folder views opens it in a dialog over the current view; global create, edit and detail workflows must not force a view change.
- Protect unsaved edits before closing, switching prompts, switching modes or changing views.

### Text selection

- The desktop shell keeps ordinary interface copy unselectable with body-level `user-select: none`. Native inputs, textareas, selects, contenteditable regions and Naive UI's native input elements must explicitly retain `user-select: text`, focus, caret and selection behavior.

## Forbidden patterns

- New `--app-*`, `--text-color-*`, `--border-color-*`, or `--code-color` variables.
- Hard-coded light/dark theme colors, arbitrary border radii or box-shadow values in components.
- Persistent shadows on cards, settings panels, tables, toolbars, or navigation.
- Structural `NCard` components with `bordered="false"`.
- Raw SVG menu icons without a sized `NIcon` wrapper.
- Amber or category colors used as button fills or large surfaces.
- Blocking browser dialogs (`alert`, `confirm`, `prompt`).
- Page-local visual systems that override the shared tokens.

## Mobile (Ionic)

Mobile pages follow the `V5 · 移动` boards: iOS-style Ionic pages that reuse the shared tokens. Desktop Naive UI layout rules do not apply to Ionic components.

- Sizes: 28/700 large titles, 22/600 block titles, 16 body and list rows, 14 secondary text, 12 captions.
- Canvas is `--surface-body`. Cards and grouped lists are `--surface-primary`, radius 16, `--shadow-card`, no border. Bottom sheets are radius 28.
- Grouped settings rows are at least 54px high and start with a 30px colored icon tile (radius 9) using category or status colors.
- Navigation is a floating capsule tab bar (prompts, models, settings). Selected tabs use `--accent-soft` with `--accent-primary` icon and text, and switch from outline to filled Ionicons.
- Touch targets are at least 44px. Primary calls to action are 50px high with radius 14; chips are 34px pills; selected chips are filled `--accent-primary`.
- Icons are `ionicons`. Ionic `--ion-color-*` variables map to the shared tokens in `assets/styles/mobile.css`; components never use Ionic's default palette colors directly.

## Implementation checklist

Before editing:

1. Identify the matching board and component-library pattern.
2. Identify whether the element is canvas, panel, nested group, control or overlay.
3. Reuse a Naive UI component (desktop), an Ionic component (mobile) or a `components/ui` primitive before writing custom CSS.

Before finishing:

1. Check borders, surfaces, radii, icon sizes, typography, hover, focus, selected, disabled, loading, empty, error and destructive states in both light and dark themes.
2. Test desktop at 1024px, 1440px and 1920px widths, and mobile at 390px.
3. Ensure global dialogs do not force a view change and unsaved-change protection still works.
4. Run ESLint, the design-system contract test, the full test suite, the main-process TypeScript build and the renderer, Web and mobile builds.
